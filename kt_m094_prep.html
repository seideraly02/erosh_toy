Композиция сложности — частая ловушка

Цикл O(n), а внутри — бинарный поиск O(log n)O(n log n)не O(n + log n)
Сначала цикл O(n), потом ещё один отдельный цикл O(n)O(n)последовательные шаги складываются, старший член остаётся
Цикл O(n), а внутри него ещё один цикл O(n)O(n²)вложенность — умножение, а не сложение

Виды деревьев — полная картина

Наивное (несбалансированное) бинарное деревоможет выродиться в цепочку, высота O(n)
BSTлевый потомок < корня < правый потомок
AVLвсегда сбалансировано, разница высот поддеревьев ≤ 1
Красно-чёрное деревотоже самобалансирующееся, использует раскраску узлов (красный/чёрный)
Двоичная куча (max-heap / min-heap)родитель ≥ потомков (max) или ≤ потомков (min)
Лесмножество независимых деревьев — это НЕ одно дерево

Задача о ранце (knapsack) — ловушка

Задача о ранце решается методомдинамического программирования, а не жадным алгоритмом
Кратчайшие пути из одной вершины, все веса ≥ 0алгоритм Дейкстры (если его нет среди вариантов — единственный из перечисленных с неотрицательными весами: не Беллман-Форд, не Флойд-Уоршелл, не Прим/Крускал — это MST-алгоритмы)

Трёхуровневая архитектура: слоиинтерфейс пользователя · бизнес-логика/алгоритмы обработки · СУБД (хранение данных)

SQL: категории команд — частая ловушка

Самая популярная ловушка на КТ: многие относят SELECT к DML, потому что он «работает с данными». На самом деле SELECT — это DQL, потому что он только читает данные и ничего не меняет.

КатегорияРасшифровкаКоманды
DDLData Definition Language — структура БДCREATE, ALTER, DROP, TRUNCATE
DMLData Manipulation Language — изменение данныхINSERT, UPDATE, DELETE, MERGE
DQLData Query Language — получение данныхSELECT (+ WHERE, ORDER BY, GROUP BY, HAVING, JOIN, DISTINCT, LIMIT)
DCLData Control Language — права доступаGRANT, REVOKE
TCLTransaction Control Language — управление транзакциямиCOMMIT, ROLLBACK, SAVEPOINT

Транзакции и изоляция

Транзакция состоит изоператоров DML, образующих одно логически цельное изменение данных
Автоматическая фиксация (auto-commit) происходит привыполнении одного оператора DML вне явной транзакции
Проблемы при параллельном выполнении транзакций (в целом)потерянное обновление, неповторяющееся чтение, фантомное чтение
Уровень изоляции READ COMMITTED предотвращаетгрязное чтение (dirty read)
price > ALL (подзапрос)больше МАКСИМУМА значений подзапроса
price > ANY (подзапрос)больше хотя бы ОДНОГО значения, т.е. больше МИНИМУМА

JOIN, NULL, агрегатные функции

CROSS JOINдекартово произведение — каждая строка левой таблицы с каждой строкой правой (n × m строк)
NULLозначает отсутствие значения — это НЕ то же самое, что 0, пустая строка '' или false
Проверка на NULLIS NULL (не = NULL)
COUNT(*)считает ВСЕ строки, включая с NULL
COUNT(column)НЕ считает строки, где column = NULL — поэтому может быть меньше COUNT(*)
COUNT(DISTINCT column)считает только уникальные значения
AVG()тоже не учитывает NULL при расчёте среднего
ORDER BY по умолчаниюASCпо убыванию — явно указывать DESC
Ограничение числа строк результатаLIMIT (MySQL) · TOP (SQL Server) · ROWNUM (Oracle)

Виды ключей

Primary Keyуникальный, не допускает NULL, один на таблицу
Foreign Keyссылается на Primary Key другой таблицы, обеспечивает ссылочную целостность
Candidate Keyлюбой из потенциальных кандидатов на роль первичного ключа
Super Keyлюбой набор атрибутов, который делает строку уникальной (может включать лишние поля)
Composite Keyсоставной ключ из нескольких столбцов вместе (например, StudentID + CourseID)

Нормальные формы

0НФесть повторяющиеся группы данных
1НФвсе значения атомарны (неделимы)
2НФнет частичной зависимости от части составного ключа
3НФнет транзитивной зависимости неключевых атрибутов
BCNFусиленная версия 3НФ, встречается реже

CRUD, индексы, DELETE vs TRUNCATE vs DROP

CRUDCreate→INSERT, Read→SELECT, Update→UPDATE, Delete→DELETE
Индексыускоряют поиск/чтение, но замедляют INSERT/UPDATE/DELETE (их тоже нужно обновлять)
Кластерный индексопределяет физический порядок хранения строк — один на таблицу
Некластерный индексотдельная структура-указатель, таких может быть несколько
DELETEудаляет строки по условию, можно откатить (ROLLBACK), структура таблицы остаётся
TRUNCATEудаляет ВСЕ строки сразу, быстрее DELETE, структуру не трогает
DROPудаляет саму таблицу целиком, включая структуру
Устойчивая (stable) сортировкасохраняет относительный порядок равных элементов (например, insertion/merge/bubble sort устойчивы, а quick/heap/selection — обычно нет)
